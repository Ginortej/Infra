# Infra

Минималистичное приложение для Windows в духе Obsidian: **серверы, VPN и лабы виртуальных машин** в одном окне.
Вся конфигурация хранится в обычной папке в виде YAML-файлов. Её удобно держать в git.

Написано на **Go + [Wails](https://wails.io)**, интерфейс на чистом JS + [xterm.js](https://xtermjs.org).

---

## Возможности

| | |
|---|---|
| **Терминалы** | Сами находит оболочки на ПК: PowerShell 7, Windows PowerShell, cmd, Git Bash, MSYS2, Cygwin, Nushell, все дистрибутивы WSL. Вкладки, `Ctrl+T`, копирование и вставка как в Windows Terminal |
| **Серверы** | SSH-терминал в один клик, группы, jump-хосты, проверка доступности, файлы по SFTP в двух панелях (ПК ↔ сервер) |
| **VPN** | Несколько профилей одновременно (WireGuard, VLESS, Trojan, Shadowsocks и всё, что умеет sing-box). Для каждой вкладки терминала и каждого сервера выбирается, через какой VPN идёт трафик |
| **Скрипты** | `.sh` по SSH на группе серверов параллельно, `.yml` через Ansible (в WSL, inventory собирается сам), `.ps1` / `.bat` локально. Отдельный вывод и код выхода у каждого сервера |
| **Лабы** | Машины VirtualBox / VMware Workstation из одного YAML: план изменений → клонирование → cloud-init (hostname, ключ, статический IP) → машины появляются в серверах → запуск плейбука |
| **Git** | Несколько аккаунтов GitHub / GitLab (включая свой GitLab), вход по токену или SSH-ключу. У каждого репозитория свой аккаунт: коммиты, push и pull идут от его имени. Изменения и diff, коммит, ветки, история, клонирование и создание репозитория на сайте |
| **ИИ-агенты** | Чат справа (`Ctrl+J`) с локальной моделью, которой можно поручить работу с серверами: команды по SSH, файлы, скрипты, VPN, лабы, git. Опасные действия — только после «Разрешить». Маркет моделей (Ollama) и готовых агентов, свои агенты со своими инструкциями и правами |
| **Безопасность ИИ** | База знаний (RAG) из Markdown-файлов: агенты сверяются с политиками, найденные правила видны при подтверждении. Запрет опасных команд, серверы «только чтение», вырезание секретов из вывода, защита от prompt-инъекций |
| **MCP** | Infra как MCP-сервер для Claude Desktop, Claude Code, Cursor: другие ИИ видят твои серверы и работают с ними через те же проверки и подтверждения |
| **ИИ-терминал** | `ollama run` во вкладке терминала, своя команда запуска для LM Studio, llama.cpp |
| **Монитор** | Виджет в заголовке: CPU, RAM, загрузка видеокарты и видеопамять; по клику — графики, температура, модели ИИ в памяти |
| **Интерфейс** | Палитра команд `Ctrl+P`, тёмная тема, без лишних панелей |

## Установка

1. Скачай `Infra.exe` из [Releases](../../releases) или [собери сам](#сборка-из-исходников).
2. Запусти. Установка не нужна. Требуется WebView2, он уже есть в Windows 10 и 11.

Дополнительно, по необходимости:

| Для чего | Что поставить |
|---|---|
| VPN | [sing-box](https://github.com/SagerNet/sing-box/releases) 1.11+. Положи `sing-box.exe` в папку `bin` хранилища или укажи путь в Настройках |
| Ansible | WSL (`wsl --install`). Сам Ansible ставится из окна запуска кнопкой «Установить Ansible» |
| Лабы | VirtualBox или VMware Workstation и шаблон VM с cloud-init (например, [Ubuntu Cloud Image](https://cloud-images.ubuntu.com/)) |

## Быстрый старт

1. При первом запуске нажми **«Создать хранилище»** и выбери пустую папку. В ней появится структура с примерами.
2. Добавь сервер кнопкой **+** на панели «Серверы» или создай YAML вручную.
3. Кликни по серверу, откроется SSH-терминал.

Хранилище меняется кнопкой с его названием слева вверху.

## Хранилище

```
my-infra/
├── servers/            серверы: один YAML на сервер, подпапка = группа
│   ├── prod/web-01.yaml
│   └── labs/<лаба>/    сюда лабы сами добавляют свои машины
├── vpn/                VPN-профили (+ .conf WireGuard рядом)
├── labs/               лабы
├── scripts/            скрипты (.sh, .yml, .ps1, .bat)
├── knowledge/          база знаний для ИИ-агентов (*.md)
│   └── security/rules.yaml   правила безопасности для ИИ
├── bin/                (необязательно) sing-box.exe
└── .app/               служебное: known_hosts, временные файлы — не коммитить
```

### Сервер

```yaml
name: web-01
host: 10.0.5.12
port: 22
user: deploy
auth: key                  # key | password
key: ~/.ssh/id_ed25519
via_vpn: work              # необязательно: SSH через VPN-профиль
jump: bastion              # необязательно: через другой сервер
tags: [web]
```

### VPN-профиль

```yaml
name: work
type: wireguard            # wireguard | singbox | socks
wireguard: vpn/work.conf   # обычный .conf WireGuard
socks: 10801               # локальный порт прокси (SOCKS5 + HTTP)
autostart: false
```

Для VLESS, Trojan и других протоколов: `type: singbox` и блок `outbound:` в формате sing-box.
Для уже запущенного стороннего клиента: `type: socks` и `proxy: 127.0.0.1:1080`.

### Лаба

```yaml
lab: k8s
provider: virtualbox                 # virtualbox | vmware
template: ubuntu-24.04-template      # VirtualBox: имя VM; VMware: путь к .vmx
snapshot: base                       # со снапшотом клоны связанные — быстро
user: ubuntu
ssh_key: ~/.ssh/id_ed25519           # публичный ключ берётся из .pub
network:
  cidr: 192.168.56.0/24
  hostonly: VirtualBox Host-Only Ethernet Adapter   # VirtualBox
  # vmnet: vmnet8                    # VMware
  # gateway: 192.168.80.2            # VMware
machines:
  - name: master
    cpu: 2
    ram: 4096
    ip: 192.168.56.10
  - name: worker
    count: 2
    cpu: 2
    ram: 2048
    ip_start: 192.168.56.11
provision:
  playbook: scripts/k8s.yml
```

## Git-аккаунты

Раздел **Git** на левой ленте.

1. **Добавить аккаунт:** GitHub, GitLab или свой GitLab (по адресу сервера).
   - **Токен (HTTPS):** кнопка «Создать токен» откроет страницу с нужными правами. Вставь токен и нажми «Проверить»: имя и почта для коммитов заполнятся сами.
   - **SSH-ключ:** выбери свой ключ или нажми «Создать ключ» (ed25519 в `~/.ssh/infra_*`). Добавь публичную часть на сайт кнопкой «Добавить через API» или вручную, потом нажми «Проверить вход».
2. **Добавить репозиторий:** папку с репозиторием, клон (список репо аккаунта подтянется сам) или новый пустой.
3. **Выбрать аккаунт для репозитория:** первая кнопка в шапке репозитория. Он сохраняется в `.git/config` репозитория (`infra.account`, `user.name`, `user.email`), так что коммиты из обычного терминала тоже идут от его имени.

**Быстрое переключение:** кнопка аккаунта в строке состояния внизу, рядом с VPN.
- Во вкладке репозитория она меняет аккаунт этого репозитория.
- В остальных местах задаёт **аккаунт по умолчанию**: от него работает `git` в новых терминалах Infra (автор, токен или SSH-ключ), и он же берётся для репозиториев без своего аккаунта.

Как это устроено: Infra запускает обычный `git`, но подставляет ему окружение выбранного аккаунта.
- Автор коммитов берётся из аккаунта.
- Токен передаётся заголовком через `GIT_CONFIG_*` (не в командной строке). Git Credential Manager для этого вызова отключён, поэтому чужой сохранённый вход не подставится.
- Для SSH используется `GIT_SSH_COMMAND` с ключом аккаунта.
- Адрес remote автоматически переписывается под способ входа (`https://` ↔ `git@`).

Токены хранятся в диспетчере учётных данных Windows, список аккаунтов — в `%APPDATA%\Infra\accounts.json`. Нужен [Git for Windows](https://git-scm.com/download/win).

## ИИ-агенты

Звёздочка на левой ленте — раздел «ИИ»: агенты, скачанные модели, база знаний и MCP. Кнопка «ИИ» в заголовке или `Ctrl+J` — чат справа, он открыт рядом с любыми вкладками.

**Маркет** (раздел «ИИ» → «Маркет моделей…»):

- *Модели* — подборка из библиотеки Ollama с пометками (инструменты, код, рассуждения, зрение) и размерами. Для каждого размера видно, влезет ли он в твою видеокарту. Установка с прогрессом, удаление, любая другая модель по имени (в том числе `hf.co/…`).
- *Агенты* — готовые шаблоны: DevOps-помощник, Разбор логов, Аудитор безопасности, Автор скриптов, Git-помощник, Лаборант, Просто чат. «Добавить» — агент появится в списке, а его модель начнёт скачиваться.

**Агент** = модель + инструкция + набор инструментов + серверы, к которым есть доступ + режим подтверждения:

| Режим | Что спрашивается |
|---|---|
| Каждый шаг | любой вызов инструмента |
| Только изменения (по умолчанию) | команды, запись файлов, запуск скриптов, VPN, лабы |
| Автопилот | ничего, кроме «особо опасного» (см. ниже) |

Инструменты: список серверов, команда на сервере, чтение / запись файлов и папки (SFTP, перед записью — резервная копия), скрипты хранилища и их запуск, VPN, лабы, git (статус, diff, история), команда PowerShell на этом ПК, поиск в базе знаний.

В чате видно каждый вызов: что, где, результат (раскрывается). Карточка подтверждения показывает команду, сервер, предупреждения политики и найденные правила из базы знаний; «Отклонить» можно с комментарием — агент его увидит. Команды из ответа можно скопировать или вставить в открытый терминал (без выполнения). История чатов — кнопка с часами.

Для агента нужна модель **с поддержкой инструментов** (qwen3, gpt-oss, llama3.1, qwen2.5-coder, mistral…). Если модель их не умеет, агент просто разговаривает. Кроме Ollama можно подключить любой OpenAI-совместимый сервер (LM Studio, llama.cpp, vLLM, OpenRouter): «ИИ: безопасность и MCP» → «Модели и провайдеры».

## База знаний и безопасность ИИ

Папка `knowledge/` в хранилище — обычные Markdown-файлы: политики, ранбуки, заметки о серверах. Кнопка «Создать с примерами» добавит политику безопасности, чек-лист аудита Linux, ранбук на случай взлома и `rules.yaml`.

- **Поиск (RAG)**: файлы режутся по заголовкам; поиск гибридный — по словам (BM25, работает всегда) и по смыслу, если скачана модель `nomic-embed-text`. Индекс обновляется сам при изменении файлов, векторы кэшируются в `.app/`.
- Агенты ищут там инструментом `search_knowledge`, а перед опасным действием Infra сама находит подходящие правила и показывает их в карточке подтверждения.

Защита работает для агентов в чате и для MCP одинаково:

- **Запрещено всегда**: `rm -rf /` и системных каталогов, `mkfs`, `dd` на диск, fork-бомба, форматирование дисков Windows + свои правила `deny`.
- **Особо опасно** — спрашивается всегда, даже в автопилоте, без «разрешать всегда»: перезагрузка и выключение, сброс фаервола, остановка SSH/сети, удаление пользователей, `curl | sh`, `DROP DATABASE`, `rm -r`, `kubectl delete`, правка `/etc/sudoers`, `sshd_config` + свои правила `strict`.
- **Серверы только для чтения** (`readonly_servers`) — агенту и MCP там можно только смотреть.
- **Секреты вырезаются** из вывода до отправки модели: приватные ключи, токены GitHub/GitLab/AWS/Slack/OpenAI, JWT, `password=…`, пароли в URL, хэши паролей + свои шаблоны `redact`.
- **Prompt-инъекции**: вывод команд и файлов передаётся модели как данные (`<data>…</data>`), текст вида «игнорируй предыдущие инструкции» помечается и подсвечивается в чате.
- Файлы с ключами (`*.conf`, `*.key`, `*.pem`, `.app/`) агенты не читают и не пишут; `rules.yaml` агент изменить не может.

```yaml
# knowledge/security/rules.yaml
deny:
  - pattern: '\bterraform\s+destroy\b'
    reason: удаление инфраструктуры
strict:
  - pattern: '\bsystemctl\s+restart\s+postgresql\b'
    reason: перезапуск базы
readonly_servers: [prod-db-01]
redact: ['MYCOMPANY_[A-Z0-9]{32}']
```

## MCP для других ИИ

«ИИ: безопасность и MCP» → MCP → включить. Infra поднимает MCP-сервер на `127.0.0.1` (Streamable HTTP, токен) и показывает готовые настройки:

```json
// Claude Desktop: %APPDATA%\Claude\claude_desktop_config.json
{ "mcpServers": { "infra": { "command": "C:\\…\\Infra.exe", "args": ["mcp"] } } }
```

```powershell
# Claude Code
claude mcp add infra --scope user -- "C:\…\Infra.exe" mcp
```

`Infra.exe mcp` — мост stdio ↔ HTTP: он находит запущенную Infra (а если она закрыта — открывает) и пересылает запросы. Внешнему ИИ доступны те же инструменты, что агентам; всё опасное подтверждается в окне Infra (появится карточка в чате и уведомление). Режим «только чтение» скрывает опасные инструменты совсем. Журнал подключений и вызовов — там же.

## ИИ-терминал

`Ctrl+Shift+A` или «+» у вкладок → «ИИ-модель» — `ollama run` во вкладке терминала.

- Нет Ollama — Infra предложит установить её через `winget` или скачать с сайта.
- Нет моделей — предложит выбрать из списка (llama3.2, qwen2.5-coder, gemma3, deepseek-r1…) или вписать любую с [ollama.com/library](https://ollama.com/library). После скачивания сразу откроется чат.
- В шапке видно, сколько модель занимает в памяти и на видеокарте. Кнопка ⏏ выгружает её (освобождает видеопамять), «Новый чат» сбрасывает контекст.
- Сервер Ollama Infra запускает сама, если он не запущен, и останавливает при выходе (только если запускала сама).
- Своя команда (LM Studio, llama.cpp): меню модели → «Своя команда запуска…», `{model}` подставится.

Виджет загрузки справа вверху показывает CPU, RAM и GPU. Для NVIDIA данные берутся из `nvidia-smi` (с температурой), для остальных видеокарт — из счётчиков Windows (как в Диспетчере задач). Клик открывает подробности. Там же виджет можно свернуть в значок.

## Как выполняются скрипты

| Файл | Где выполняется | Как |
|---|---|---|
| `.sh` | на выбранных серверах | по SSH: `bash -s < скрипт`, параллельно; можно через `sudo -n` |
| `.yml` | на выбранных серверах | `ansible-playbook` в WSL; inventory собирается из выбранных серверов, ключи копируются в WSL |
| `.ps1` | на этом ПК | PowerShell 7 или Windows PowerShell |
| `.bat` / `.cmd` | на этом ПК | cmd.exe |

Перед запуском открывается окно: тип скрипта, где и как он выполнится, выбор серверов и итоговая команда.

## Безопасность

- **Пароли и пароли ключей не пишутся в YAML.** Их спрашивают при подключении и, если хочешь, сохраняют в диспетчер учётных данных Windows (Credential Manager).
- Ключи хостов проверяются: новый сохраняется в `.app/known_hosts`, а **изменившийся ключ блокирует подключение**.
- Временный inventory для Ansible (там могут быть пароли) удаляется сразу после запуска.
- ИИ-агенты и MCP проходят политику безопасности (см. «База знаний и безопасность ИИ»), секреты вырезаются из вывода, опасное подтверждает человек. MCP слушает только `127.0.0.1` и требует токен; токен и ключи API хранятся в настройках пользователя / диспетчере учётных данных, не в хранилище.
- В `.gitignore` уже есть `.app/`, приватные ключи, `*.conf` (WireGuard) и `.env`. Хранилище с реальными серверами лучше держать в **приватном** репозитории.

## Сборка из исходников

Нужны Go 1.24+, Node.js 20+ и Wails CLI:

```powershell
go install github.com/wailsapp/wails/v2/cmd/wails@latest
wails build              # результат: build\bin\Infra.exe
wails dev                # режим разработки с перезагрузкой
go test ./...            # тесты бэкенда
```

Интерфейс можно запускать в браузере с тестовыми данными, без Go: `cd frontend && npm install && npm run dev`.

## Ограничения

- Только Windows: локальные терминалы работают через ConPTY.
- Ansible не пройдёт к серверам за VPN, если в WSL не включён режим сети `mirrored` (`networkingMode=mirrored` в `.wslconfig`).
- Изменения CPU и RAM в YAML лабы применяются только при создании машины.
- Режим TUN (VPN для всей системы или отдельных программ) пока не поддерживается: профили работают как локальные прокси.
